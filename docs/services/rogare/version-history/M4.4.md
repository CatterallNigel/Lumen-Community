# Lumen Rogare M4.4 — Presentation History Reattachment

## Acceptance

The milestone is accepted when a live Rogare session can move between embedded Servire presentation and the direct Rogare window while preserving both conversational continuity and the visible user/assistant transcript.

### Required behaviour

- Session identity remains the same across presentation changes.
- Pontis binding validation remains authoritative before reconnect.
- User and assistant presentation events are stored against the active Rogare session.
- Reattachment rebuilds those visible messages in chronological order.
- System notices, errors, tool traffic, ACP bootstrap content, and Moderari internal context are excluded.
- Starting a new session clears presentation history rather than inheriting an older transcript.
- A stale or unverifiable Pontis binding clears browser session state and does not restore presentation history.
- Transcript storage is bounded to the most recent 200 visible messages.

## Responsibility boundary

Moderari remains responsible for model context and continuity. Pontis remains responsible for provider/session arbitration. Rogare owns the user-facing transcript. Presentation restoration therefore does not attempt to reverse-engineer a UI transcript from raw model context.
