# Lumen Rogare M4 — Conversational UI

## Objective

Replace Postman as the normal Rogare conversational surface while preserving Rogare's architectural boundary as a tool-less client.

## Behaviour

`GET /` serves the first Lumen-native Rogare conversational UI.

The UI:

- starts a named Rogare session through `POST /api/console/session/start`;
- displays Pontis/provider readiness, discovered capability count, selected model and ACP session identity returned by Pontis;
- submits normal user turns through `POST /api/console/message` using the same Rogare session ID;
- renders OpenAI chat-completion assistant content as conversation output;
- shows an explicit running/activity state with elapsed time during long Lumen/model/tool operations;
- preserves the existing M3.2 long-running HTTP timeout as the transport safety envelope.

Rogare does not inspect, execute, translate or route tools. Pontis remains the provider/session/capability arbiter.

## Heartbeat note

M4 deliberately does not yet expose Moderari heartbeat frames directly to the browser. The UI presents local elapsed-time liveness while the existing blocking API request is active. A later UI milestone should propagate Moderari heartbeat/progress events so the visible activity is driven by real downstream progress rather than only a local running timer.

## Network identity

Rogare's canonical local port is `11432`. Servire remains on `11439`.

## Acceptance

1. Open `http://127.0.0.1:11432/`.
2. Start `rogare-test-1` and confirm provider/capability/model state becomes ready.
3. Submit a tool-using prompt such as `pwd`; the UI remains visibly active while the operation runs and eventually renders the final assistant answer.
4. Submit further prompts on the same session, including a different tool such as `read`, without starting a new session.
