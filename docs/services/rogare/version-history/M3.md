# Lumen Rogare M3 — Pontis Session Context

## Objective

Maintain one logical Rogare conversation through Pontis without coupling Rogare to Pi or ACP.

## Contract

For every OpenAI-compatible chat-completions request Rogare sends to Pontis:

- the Rogare `session_id` remains in the OpenAI `user` field for compatibility;
- the same value is also sent as `x-lumen-session-id`;
- if `pontis.working_directory` is configured, it is sent as `x-lumen-cwd`;
- Rogare declares no tools and executes no tools.

Pontis may use the Lumen session header to associate a lazily-created provider session with the same logical conversation. The working directory is provider-session context only and does not make Rogare provider-aware.

## Acceptance

- repeated turns using one Rogare session emit the same `x-lumen-session-id`;
- the optional working-directory header is stable across those turns;
- the OpenAI request body remains protocol-compatible and contains no Pi/ACP-specific fields;
- existing M1/M2 behaviour remains covered.
