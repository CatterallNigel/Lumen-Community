# Lumen Rogare M3.2 — Long-running Pontis Requests

## Purpose

Rogare must not terminate a valid Lumen model/tool cycle merely because it takes longer than two minutes.

## Change

- Default `pontis.timeout_seconds` increased from 120 seconds to 7200 seconds.
- The configured timeout governs long-running response reads.
- Pontis connection establishment remains bounded to at most 10 seconds, so an unavailable Pontis service still fails promptly.
- `pontis.timeout_seconds` remains configurable in `config.yml`.

## Operational reason

The Rogare → Pontis → Moderari → tool-provider acceptance run completed successfully downstream after roughly four minutes, but Rogare had already timed out at 120 seconds and returned HTTP 502. M3.2 keeps Rogare aligned with Lumen's long-running conversational operations.
