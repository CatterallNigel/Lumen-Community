# Rogare M2 — Pontis / Lumen Stack Integration

## Goal

M2 proves both the Rogare-to-Pontis transport path and the protocol-compliant conversational path into the Lumen stack while preserving Rogare's tool-less boundary.

```text
Rogare -> Pontis -> Vestigare -> Repetere -> Moderari -> Model
```

Rogare does not contain Pi, ACP, tool discovery, provider lifecycle, or tool-execution code.

## M2.1 Connectivity probe

Rogare exposes:

```http
POST /api/console/pontis-probe
```

The probe deliberately sends a payload to Pontis `/v1/chat/completions` that is **not** OpenAI chat-completions compatible. Pontis is expected to accept the HTTP request and transparently forward it. The downstream Lumen stack is expected to reject it.

A returned HTTP response proves that Rogare reached Pontis. A Moderari-specific error in the returned response and/or Moderari logs confirms that the request traversed the Lumen stack.

Rogare does not claim to identify the downstream component merely from the HTTP status code.

## M2.2 Protocol-compliant conversation

`POST /api/console/message` converts Rogare's internal conversational request into a minimal OpenAI-compatible chat-completions request:

```json
{
  "model": "lumen",
  "messages": [
    {"role": "user", "content": "Hello"}
  ],
  "stream": false,
  "user": "rogare-session-id"
}
```

The model name is configurable under `pontis.model`.

Rogare metadata remains Rogare-side metadata and is **not** inserted into the OpenAI-compatible wire payload. This avoids introducing non-standard fields into strict downstream implementations.

## Error transparency

M2 distinguishes transport failure from downstream rejection:

- If Rogare cannot obtain an HTTP response from Pontis, Rogare returns `502 Bad Gateway`.
- If Pontis returns an HTTP error response, Rogare preserves that HTTP status and returns the downstream body as the error detail.

This allows a Moderari validation error to remain visible during integration rather than being hidden behind a Rogare-generated `502`.

## Success criteria

M2 is successful when:

1. `POST /api/console/pontis-probe` reaches Pontis and the deliberate malformed request can be observed reaching/rejected by Moderari.
2. `POST /api/console/message` sends a valid OpenAI-compatible request through Pontis.
3. A successful model response can return through the Lumen stack and Pontis to Rogare.
4. Rogare owns no tools, provider sessions, ACP code, or Pi implementation.
5. Unit tests, Ruff, mypy and coverage checks remain clean.
