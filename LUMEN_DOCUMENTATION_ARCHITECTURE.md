# Lumen Documentation Architecture

**Status:** Architecture  
**Version:** 1.0

---

# Purpose

Define how documentation is organised across the Lumen++ ecosystem.

The objective is to maintain a single authoritative source for each significant engineering topic.

---

# Documentation Hierarchy

Research

↓

Architecture

↓

↓

↓

↓

---

# Document Types

## Research

Long-form exploration of ideas, experiments and theory.

## Architecture

Canonical description of how a component is designed.

## Overview

Concise introduction suitable for first-time readers.

## Runtime Guides

Operational and development procedures.

## Engineering Diary

Chronological record of decisions and milestones.

## Microsite

Public-facing distillation of the engineering documentation.

---

# Canonical Documents

Every significant topic should have one canonical engineering document.

Other documents should reference or summarise that source rather than duplicating its content.

---

# Guiding Principles

- One authoritative source.
- Distil rather than duplicate.
- Keep responsibilities clear.
- Update canonical documents first.
- Allow the microsite to evolve from the documentation, not independently of it.
